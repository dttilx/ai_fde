# APX-240 设计补充方案：Jev 检索治理、轻量权限与考试要求补齐

日期：2026-10-04  
版本：0.1.0（审核稿）  
状态：新增设计提案，尚未实现；不替代当前 spec、plan、契约和 tasks。审核后需要将变更同步至正式制品，才能进入实现。

## 1. 目标、依据和范围

目标是让个人项目具备可现场演示的特色，同时完整遵守考试第六题及 APX-240 补充手册。新增能力服务于证据质量、授权边界和资料保护，不建设企业权限平台。

依据：题库第六题与统一交付要求；补充手册第 3 页 SAFE-01～05、第 4 页七个报警码、第 5～6 页历史及工单使用约束、第 7 页输出与市售模型要求；Constitution 1.0.0；现有规格与 LangGraph 设计。

保留四项展示重点：可纠正的多模态证据、可暂停恢复的诊断、带检索治理与引用检查的报告、审核后才沉淀的案例。Jev 是 RAG 检索结果处理的明确组成部分，不只是未来可选项。

仍采用 Next.js/React + FastAPI 模块化单体 + PostgreSQL/pgvector + MinIO + PostgreSQL Job/checkpoint。继续禁止设备控制、训练、GraphRAG/Neo4j和预测维护。只运行单组织演示，保留资源归属字段；不做多租户运营、SSO、策略引擎、自动保修理赔或完整证书管理。

本方案不授予考试资料外发许可、不调用付费模型、不创建账号、不运行任务。提案里的限额与门槛是待验证的产品配置，不是题目原文或已测指标。

## 2. 模块与完整流程

沿用 incidents、evidence、safety、diagnosis、knowledge、expert、feedback 和 shared。新增轻量 access 模块负责账号、资源范围、资质和授权审计；资产与保修信息仍归 incidents/assets，不新增复杂服务平台。

knowledge 下增加 passage_assessment 服务与 Jev 适配器；shared/providers 增加统一外发策略检查，所有外部模型均经过它。

正常路径：

1. 后端验证身份和事件范围，创建事件；明确危险描述立即产生基于规则的安全通知，不等待 OCR、外部模型或保修信息。
2. 用户复核媒体候选证据；prepare 固定原始输入、确认事实与证据版本。
3. safety_gate 执行 SAFE-01～05；阻断时输出停止与升级要求，不进入普通检索。
4. 构建检索范围，精确查询报警码，并执行按授权过滤的关键词/向量检索。
5. 固定必要来源、混合排序、去重、限额；逐片段检查外发许可，生成最小化输入。
6. Jev 对允许处理的候选片段评估相关性、适用性、潜在矛盾和异常指令；规则合并其结果与未外发的来源。
7. decide 判断继续检索、补充信息、专家接管或报告生成；事实冲突与未知风险继续受 SAFE-05 约束。
8. LLM 在自身外发许可范围内生成草稿；校验事实、排序、报警码步骤与每项引用。
9. Jev 对允许外发的“陈述—引用”对作支持性检查；其他陈述转本地规则或人工复核，不能伪称已检查。
10. 人工复核发布；后续专家修订、维修结果、案例审核各自追加版本。

LangGraph 仍只有 prepare、safety_gate、retrieve、decide、ask_information、expert_review、finalize 七个节点。检索评估作为 retrieve 的子服务；引用支持性检查作为 finalize 的子服务，不扩展第二套编排框架。

## 3. 两类资料与独立外发许可

### 3.1 业务资料分类

| 分类 | 示例 | 默认业务访问 |
|---|---|---|
| TECHNICAL_REFERENCE 通用技术资料 | 手册、安全规则、报警码、允许共享的历史案例 | 本组织中获授技术资料读取权限的人员 |
| FIELD_RECORD 现场敏感资料 | 资产、原始图片/视频、事件、维修工单、专家报告 | 按事件/设备分配与明确授权 |

“通用”不表示公网公开，也不表示可发给外部模型。考试手册、题库派生的工单或切块都继承其保密约束。历史案例和已审核案例按实际来源及共享范围分类，不凭名称自动扩大访问。

第一阶段技术资料限一个演示组织。现场资料按创建者和事件成员授权；审核人仅访问分配给自己的候选案例与必要证据。

### 3.2 外发是第二道独立检查

每份来源记录 egress_policy：DENY、APPROVED_REDACTED 或 APPROVED_RAW；记录许可依据、允许的 provider/purpose、版本、有效期。默认 DENY，许可继承到切块、摘要、向量、关键帧和报告。

外发前要求：当前处理范围有权读取；来源许可覆盖目标 provider 与用途；输入现场事实及片段都允许外发；脱敏与最小化合格。任何一项不成立，都不能调用对应外部 provider。

不是“用户自己能看见就能送 Jev”，也不是“把名字删掉就不再保密”。脱敏不产生新的许可。不得把受限来源放进 questions/instructions、重试日志或公开 Playground 链接来规避检查。

政策适用于 Jev、LLM、VLM 和远程 embedding，不仅是检索后的 Jev。受限来源的 embedding 采用本地适配器；不能先外发生成向量，再宣称检索有权限隔离。

真实 Jev 验证可以先用有合法处理依据的自建模拟材料。考试原文外发需核对其许可；未确认时保持受限，系统仍显示 Jev 处理位置及明确跳过原因。禁止把 fixture 回放标成真实 Jev 调用。

## 4. 身份、范围与维修资质

### 4.1 身份方案

个人版使用后端本地账号与不透明会话 ID，浏览器 Cookie 为 HttpOnly；非本机部署启用 HTTPS/Secure，写接口校验 CSRF。会话与账号状态存 PostgreSQL，无须 Redis。密码使用成熟密码哈希库，不保存明文。

ActorContext 由后端解析，包含 actor_id、organization_id、角色集合、事件/资产范围和 authorization_version。API 的身份、角色和组织字段不由调用者声明获得权限。账号停用、退出和授权撤销应即时影响新请求。

初始账号与资质由本地受控管理命令维护，不建管理后台。管理员可配置授权但不自动具备诊断审批或维修资格。企业 SSO 留给后续适配。

### 4.2 角色和资源范围

| 动作 | 角色与资源条件 |
|---|---|
| 报障、上传、证据复核、回答追问 | FIELD_ENGINEER 或 EXPERT，且有事件/资产对应权限 |
| 查看事件、报告、媒体、引用、Job/SSE | 有对应资源读取权限，不能只按角色允许 |
| 专家接管、修订、冲突处理 | EXPERT 且已分配该事件；不能解除安全禁止 |
| 提交维修结果 | 事件授权人员，记录实际维修执行者；代录需留审计 |
| 审核/发布案例 | CASE_REVIEWER 且分配审核范围；EXPERT 不自动包含发布权 |
| 授权维护 | 本地管理权限，不自动获得全部现场资料内容 |

Expert 和 CaseReviewer 可以由同一账号兼任，但需分别授予。默认不允许提交者自审；演示例外需显式配置、标记并审计，不能伪称独立审核。

单组织数据仍有 organization_id。QR 仅是资产查询键，知道 QR 或事件 ID 不产生访问权；未知资产与无权资产对普通用户不透露敏感存在性。

### 4.3 实际维修资质

QualificationGrant 至少记录 actor_id、资质类别 ELECTRICAL/MECHANICAL、授权来源、授予人、有效期、适用资产范围和状态。以手册 SAFE-04 的电气/机械授权为最低要求，气路、伺服等动作通过手册依据映射，不虚构行业证书制度。

报告步骤保留技术建议，同时标注 required_qualification 与 execution_boundary。无对应资质则显示“由相应授权人员处理”并进入专家转交；业务专家身份不替代资质。实际安全隔离条件由现场人员确认，系统不发操作许可，不控制设备。

复机验证结果必须包含执行者、结果和证据。AI 不确认最终根因，Jev 不计算人员资格概率。

## 5. 检索访问控制与存储权限

构建 RetrievalScope：organization_id、事件 ID、允许资产/共享范围、knowledge_release、authorization_version。结构化查询、关键词查询、向量查询使用同一 scope，在数据库查询阶段过滤；未审核 CaseDraft 永不进入生产检索。

不得在全库 top-k 后才删除无权文档。演示数据量小，可以在授权集合中执行精确向量距离计算；未来若启用近似索引，需要验证过滤后召回数量及跨范围隔离。

关键词与向量各取至多 20 项，用 RRF（初始 k=60）融合去重，再取至多 8 个非必要候选。必要来源独立保留，不挤占所有候选；优先保持手册、案例和工单的来源多样性。参数可调整，发布时固定版本。

数据库第一阶段采用统一授权服务、带 scope 的仓储接口、跨用户集成测试。分离应用和迁移账号；知识发布只允许受控入口。没有独立多套向量数据库、权限服务或强制 RLS。未来扩展组织隔离时再评估数据库 RLS。

MinIO 私有 bucket，资源权限检查后发短时 URL（建议 60 秒），缩略图与关键帧继承原媒体权限。已发 URL 在有效期内可能继续可用，不能承诺即时撤销；需要严格撤销的原始媒体采用后端鉴权代理下载。

SSE、Job、checkpoint、下载和引用接口均检查所属事件。检索/评估缓存包含来源 checksum/release、输入 hash、scope/authorization_version、egress_policy_version、问题和模型版本；命中缓存后重新校验当前权限。

诊断输出继承其依赖来源的可见范围；不得通过摘要或原因文本泄露用户无权读取的工单。共享报告需去除受限来源衍生内容或重新在较窄 scope 中生成。案例审批、脱敏、共享范围批准是三个独立检查。

## 6. Jev 作为 RAG 检索后处理层

### 6.1 接入与责任

PassageAssessmentProvider 有 Jev、fixture 两条明确路径；一般混合检索作为透明降级。正常且已授权外发时，检索返回候选必须经过 Jev 阶段，不能默默绕过。UI/manifest 标记 Jev 实际成功、部分成功、无候选、权限跳过、超时或 fixture。

Jev 接口采用官方 Python SDK 的异步客户端，或等价 HTTP 适配器；固定实际可用具体模型版本，不以 jev-latest 作为可复现实验版本。返回的实际模型 ID 同时记录。不直接依赖 OpenAI-compatible 接口，因为 Jev 使用不同的 System One 契约。

### 6.2 原子问题设计

逐个候选建立“已确认事实的最小摘要 + 一段来源及必要上下文”的 state；明确指出历史事实不是当前事实。片段可能含正常操作建议，不能把“维修建议”一律当提示注入；异常指令问题只识别试图改变系统规则、索取秘密或越权的内容。

| 问题 | 原语与选项/等级 | 用途 |
|---|---|---|
| 与当前故障是否相关 | Score：无关、背景、部分相关、直接相关 | 辅助重排，绝非故障概率 |
| 如何使用这段来源 | Choice：当前事实的技术支持、历史参考、仅背景、无关、无法判断 | 来源适用性 |
| 是否存在需要核实的矛盾 | Choice：无明显矛盾、历史差异、当前事实冲突线索、无法判断 | 冲突分流 |
| 是否试图越权指挥模型 | Noul，标准明确写在 instructions | 标记异常指令风险，不能作为唯一防线 |

question key 仅用于映射返回值，官方说明它不参与推理；所有判断条件及片段定位必须在 instructions/state 中完整表达。

同一候选多个问题一次提交；不同候选最多并发 2 个请求，避免全库逐片段分析与大规模并发。第一版最多 8 候选，不把整份手册、整个事件或全部 checkpoint 发给 Jev。

### 6.3 合并与路由规则

1. 本地已审核 SAFE 规则和匹配报警码顺序作为 pinned source，低 Jev 分也不能删改；手册依据在本地可定位。未授权资料不能以 pinned 为名进入用户上下文。
2. 非必要候选保留 hybrid_rank 与 Jev 评估，按来源可靠性、适用性和相关性排序。首版只有明确无关、无冲突、低相关且评估确定的片段才能排除，其余进入证据、背景或待复核集合。
3. 历史温度、压力与当前不同是 historical_difference，不自动触发 SAFE-05；两条当前确认读数互斥、权威指令矛盾或风险不明才进入 CONFLICT_BLOCKED/专家。
4. Jev 发现当前事实冲突线索时保留片段并暂停核实，不能删掉矛盾来获得看似一致的报告。代码能计算的数值、日期和单位由代码验证。
5. 来源中攻击指令与正文均是数据，不产生工具或授权；高风险异常指令进入隔离/人工核实。若被隔离的是必要资料，不把它当普通无关项丢弃后继续生成；应报资料完整性问题并升级。
6. 被外发策略阻止但允许当前主体读取的片段标记 SKIPPED_POLICY，保留其原始排序和来源，不因没有 Jev 分而降低必要证据权重。
7. 候选全无相关支持时，SAFE-05 无覆盖升级；所有评估不确定则请求必要信息或人工复核，不能凭空生成。

首版不采用概率乘积计算根因概率。Score 与 confidence 只用于来源适用性和人工复核分流；数值阈值需基于标注样例确认。可以配置保守初值，但未经评估不得自动宣称“已验证支持”。

### 6.4 超时、预算和降级

提案初始限制：每个 Jev 请求 3 秒超时、整轮评估最多 15 秒；可重试错误至多重试一次，并计入整轮预算；并发 2、普通候选 8。SDK 默认重试必须覆盖为显式受限配置，不能与 Job 重试叠加造成失控。

共享 Agent 总预算沿用最新 tasks：32 步、3 轮检索、5 个不同追问、20 次工具/外部请求、12,000 Token、5 次恢复、120 秒累计活动时间；每个 Jev 请求及重试均计数，提供者 usage 计 Token。请求前预留预算，超时消耗时间且记录用量未知，不能重置预算。若 8 候选超过剩余预算则缩减候选数量或停止，禁止通过一次批处理名义隐藏多个请求。

没有 key、外发被阻止、429/529/超时等均明确记为 PARTIAL/UNAVAILABLE/SKIPPED_POLICY，保留本地必要来源和普通混合检索。评估失败不自动转为“无关”或“已通过”；不能代替缺失事实。剩余检索证据够用时形成需人工复核草稿，否则补充/升级。

无 key 的 fixture 测试只证明流程，真实展示至少在允许外发的模拟资料上运行 Jev，显示实际模型版本。现场页面不能掩盖模型模式或资料受限原因。

## 7. 引用、报告与手册要求补齐

### 7.1 报告分区

fault_phenomenon 按事实复述。known_facts 仅包含本次确认事实并关联 evidence_id；confirmed_observations 单列视觉/声音观察，不把观察推成内部根因；unconfirmed_information 与 contradictions 独立数组；manual_references 单列标准参数，不能成为当前设备读数。

possible_causes 保留 POSSIBLE，增加 rank、supporting_evidence_ids、citation_ids、counter_evidence_ids、missing_evidence 和 ranking_reason；排名基于明确支持/差异，不输出未经校准的根因概率。报告整体 confidence 不作为强制字段，改为 evidence_sufficiency 与 limitations；Jev confidence 属于模型评估记录。

historical_comparisons 记录 source_ref、相同点、差异、缺失信息、解释影响及关联当前证据。H02 中的 H1 开路是历史确认根因，当前事件只能是可能原因。专家最终确认另存，不改写 AI 的 POSSIBLE。

check_sequence 与 safety_preconditions 每项仍有 citation_ids；步骤增加 alarm_step_ref、required_qualification、execution_boundary、适用时的 service_policy_refs。允许安全升级报告没有普通排查步骤，安全通知承担立即停止动作；不为满足 minItems 填入危险步骤。

停止条件与升级原因增加输入/规则依据引用。需要补充的信息显示对应缺失证据与必要性，避免反复索取无诊断价值的字段。

### 7.2 报警顺序与历史差异

七报警 seed 按手册第 4 页转为带 step_id 的标准模板，保留“→”先后和前置条件。允许跳过已确认完成的步骤，但记录完成依据；不能跳过安全隔离或授权要求。自动验证报告步骤无非法倒序。

A205 是报警码明确要求立即停机、隔离、冷却、专家检查，即使用户未描述焦味也执行相应阻断。A401 禁止绕过联锁；A520 若有金属摩擦危险则 SAFE-01 优先。A310 的 H03 泄漏与 WO-240-051 滤芯堵塞是候选参考，不是相互矛盾的当前事实。

### 7.3 引用检查

先用代码检查 ID、checksum、release、定位、访问权及引用摘录匹配；再以“一个陈述 + 引用必要上下文”调用 Jev Choice：支持、矛盾、未支持、无法判断。多个来源可联合解释，但不得让单一历史来源证明当前根因已确认。

允许外发才检查。支持性不确定或被策略阻止时标记人工待复核；决定性陈述出现矛盾必须移除/修正并核实，不能人工按一下确认就原样发布。历史支持足够并不解除危险规则。最终发布仍经过明确人工复核，Jev 不是最终根因审批人。

首版限制模型草稿自动修复最多 1 轮，仍失败就人工或升级；计入总预算。Jev 引用检查可以先覆盖原因陈述，安全/报警步骤采用审核规则模板与一致性验证，避免逐步大量 API 调用。

## 8. 资产、保修和视频边界

Asset 增加 serial_number、organization/site、service_contact，以及可选 WarrantyRecord：起止日期、UNKNOWN/ACTIVE/EXPIRED、政策来源、确认人、版本。日期比较由代码执行。没有合同则政策未知，不生成“自修会失去保修”的断言，不阻断报障与紧急安全提示。

ServiceRestriction 最小字段是适用动作、要求（例如指定服务方）、依据和有效版本。只管理显式条款，不自动审批或理赔。若受限动作是必要下一步，则转服务方/专家确认，继续展示已有事实和停止条件。

初始媒体限额建议：图片最多 5 张、单张 10 MB；视频单个 60 秒/100 MB，最多 8 帧；限额需做实际格式/解码校验。视频只分析关键帧、时间点和可观察视觉现象。声音由用户按时间点确认，source 为 TEXT/FORM 并关联视频定位；没有真实音频分析适配器时不得生成自动摩擦/漏气声识别结果。

资料保密、访问控制适用于原图、缩略图、音轨与关键帧。默认不在公共仓库提交题库和手册原件；演示保留虚构考试设备标识。

## 9. 暂停恢复与权限变化

Job 暂停成功结束当前片段并释放 worker，恢复新建 Job 延续同一 thread。信息、证据变化恢复后先执行安全门；累积预算、租约、checkpoint 版本、幂等与取消保护保留。

恢复时重新检查有效账号、事件权限、所需角色和资质、当前外发政策；冻结在 manifest 的旧权限仅用于审计，不是当前权限凭证。检查点保存受控服务引用，不保存 Cookie/API key。

等待专家和冲突阻断是可恢复状态，与最终 ESCALATED 分开；需在正式数据模型中统一公共 DiagnosisRun 状态，不能把全部等待映射为终止。

第一版一个诊断运行的资料范围不随专家加入而扩大：专家可以查看获授权的附加资料，但若要把超出原运行范围的资料用于新诊断，应创建关联的新 run，原 run 保留待处理/升级状态。不得把专家的高权限 checkpoint 原样交回工程师。

已撤权的来源不得继续用于新节点或恢复输出；冻结原快照保留受控审计。如必须改变来源范围，创建相关新 run，不能原地删改快照或用新 run 偷绕相同诊断的预算；关联事件的自动预算不重置，重新运行例外需记录人工理由。

## 10. 最小数据增量与接口约定

| 对象/字段 | 最少内容 |
|---|---|
| User / Session | 账号状态、密码哈希、组织、会话、有效期 |
| RoleGrant / IncidentMember | 角色集合、事件角色/范围、授予人、authorization_version |
| QualificationGrant | 专业类别、资产范围、依据、有效期与状态 |
| KnowledgeSource / Chunk | 业务分类、组织、共享范围、egress_policy、来源与发布版本 |
| Asset / WarrantyRecord | 序列号、现场、服务方、可选保修和政策版本 |
| PassageAssessment | 运行/来源/问题版本、具体模型、分布、路由、状态、输入 hash、用量和延迟 |
| CitationAssessment | 陈述 ID、citation_id、关系、复核状态与实际处理模式 |
| DiagnosisManifest 增量 | authorization/egress/ranking 版本、Jev 模型及问题、调用用量、降级、检索选择与排除依据 |

业务事件审计记录操作者、动作、资源、结果、理由和版本。生产日志只保留受控引用/hash，不打印原始现场资料；诊断记录内按权限保留可复核评估，不存隐藏推理。

接口建议：

- POST /api/session、DELETE /api/session、GET /api/me：获取可信身份与有效角色。
- 现有事件/证据/Job/SSE/引用接口统一经过 access 服务；403 或防存在性泄露的 404 按契约一致处理。
- GET /api/diagnoses/{id}/retrieval-assessments：仅返回有权限的来源、选择依据和处理状态，不返回未授权来源清单、原始 Prompt 或 secrets。
- GET /api/diagnoses/{id}/citation-assessments：逐陈述显示规则校验与 Jev/人工复核状态。
- resume 接口仍使用 checkpoint_version、idempotency_key 和 payload；删除客户端自报角色作为授权依据。
- 维修提交新增 executor_id、资质依据与复机证据；案例审核新增 publication_scope 和脱敏确认。

正常检索评估是 Diagnosis Job 内部步骤，不另开用户可随意访问的独立“全库 Jev 查询”接口。

## 11. 展示方式与独立验收

页面增加两个轻量面板：检索依据（必要保留/相关/历史差异/待核实）与引用检查（支持/不支持/矛盾/未复核）。显示真实 provider 模式；一般工程师不显示全库排除计数、他人事件或权限泄露线索。可选择展示相关等级而非难解释的模型概率。

| 场景 | 可执行的通过条件 |
|---|---|
| A203 完整信息 | A203/H02/WO-240-042 可定位；H1 仅 POSSIBLE；历史读数对照、原因排序说明与电气资质边界完整 |
| A310 缺失信息 | 追问上游/设备端压力与漏气证据；不确认接头松动；补充恢复同线程且先查安全 |
| SAFE-01 | 明确危险描述立即停机/升级，不等待 Jev；人确认后仍不能危险试运行 |
| A205/A401/A520 | A205 无额外危险描述仍停止；A401 不绕联锁；A520 摩擦声走安全升级 |
| A101/A900 | 安全顺序与手册一致，缺信息追问，无引用不输出凭空原因 |
| Jev 重排 | 允许外发的模拟来源真实调用；去除明显无关片段，必要来源低分仍保留，保留历史差异 |
| Jev 语义错误 | 打乱 Choice 选项、不同措辞、中文输入、矛盾和攻击样例；不能绕安全/权限；记录实际错误，不预填成绩 |
| 引用失败 | 不存在 ID、错版本、历史当当前根因分别被代码/语义检查/人工复核阻止发布 |
| 无 key/超时/限流 | 显示真实降级，保留规则与合规来源，不伪称 Jev 已通过；预算仍累计 |
| 跨事件读取 | 工程师 A 访问 B 的事件、媒体、Job、SSE、引用、checkpoint 均被阻止，QR 无法绕过 |
| 外发禁止 | 读取允许但外发禁止的片段不出现在任何外部请求，包括 embedding、questions、日志与重试 |
| 外发继承 | 报告/摘要/关键帧继承来源限制，已审核案例未获共享许可不扩大访问 |
| 权限撤销与恢复 | 撤销范围或角色后禁止 resume；缓存不泄露；专家高权限资料不进入原工程师 run |
| 维修审核 | 非授权角色不能发布，缺复机证据不能审核；发布范围独立批准，原版本保留 |
| 声音与保修未知 | 未配置音频模型不自动识别声音；未知保修不推断合同限制 |
| 现场交付 | 实际可打开入口、输入说明、规则使用、输出字段、真实市售模型自测输入输出和版本都齐全 |

真实模型评估首批建议至少 21 个标注文本场景（每报警至少 3 个，含完整/缺失/差异）及额外安全、权限、引用和失败样例。比较有/无 Jev 的候选相关性、必要来源保留率、冲突保留、错误陈述拦截、延迟和成本。小样本结果只描述演示集合，不宣称工业准确率。

必要来源保留、权限隔离、危险阻断在确定性回归集合要求零失败；真实模型质量记录实测值，不能以厂商宣传替代。Jev 阈值发布需绑定这批输入/输出/模型/问题版本，后续变化重新验证。

## 12. 审核后同步顺序与现存差异

先更新 spec：新增 Jev 检索处理、两类资料、外发边界、维修资质、历史比较和真实模型验收；声音范围收敛为视觉分析加人工声音确认。Constitution 不放宽任何原则。

再同步 plan/research/data-model/contracts/quickstart：公共图状态、同线程恢复与报告版本、32 步/120 活动秒预算、身份契约、报告字段与 Jev 状态一致。将 SC-005 “90% 有引用”改成所有发布报告必须逐项引用，模型草稿失败可以复核/拒绝，不能作为发布例外。

最后更新 tasks 增加对应垂直切片和回归，进行只读一致性分析后实现。本次仅输出审核方案，不修改正式制品、不生成任务或业务代码。

已有设计仍需统一：research 的 8 步与 tasks 的 32 步；等待专家与终止升级映射；/information 的新版本表述；恢复后安全检查；原始 OCR 候选冲突与确认后的事实冲突；report 的 UNCONFIRMED/CONTRADICTED 与 known_facts 混用。这些不能被新增 Jev 覆盖而忽略。

## 13. Constitution Check 与待核实配置

| 原则 | 本方案处理 |
|---|---|
| 安全优先 | 独立前置规则，Jev 无权修改，报警特殊停止仍优先 |
| 事实边界与复核 | 仅确认媒体进入诊断，历史差异不等于事实冲突；人工声音明确来源 |
| 有界 Agent | 每个 Jev 请求/重试计预算，人工等待不计活动时间，跨恢复累积 |
| 分层知识与引用 | 混合 RAG、必要来源保留、来源版本、逐陈述支持检查，无 GraphRAG |
| 人工负责与不可覆盖 | 最终根因人工确认，修订追加，案例审核及共享范围批准 |
| 模块化与个人可维护 | 单组织、本地会话、轻量 grants、单数据库，不增加权限平台或视频训练 |

设计层面未放宽 Constitution；最终合规仍取决于正式规格同步与实现验收，不把“设计检查”写成已通过测试。

待核实但不阻断本地设计：考试资料是否允许特定外部模型处理；Jev 账号可用性、实际可固定模型版本、数据留存/地域/条款；外部 LLM/VLM 同类条件；媒体限额与时间门槛实测。未核实资料默认禁止外发，可用受控模拟资料和 fixture 验证。

## 14. 外部技术依据

以下是 TypeSafe 官方能力描述，不证明 Jev 在 APX-240 上的实测表现：

- [System One API](https://docs.typesafe.ai/api)：state + typed questions，Choice/Score/Noul，返回实际模型与 usage，key 不参与推理。
- [RAG 片段分类](https://docs.typesafe.ai/cookbooks/classifying_rag_passages)：检索后多维评估，分开证据与冲突；本项目增加访问与外发检查，不照抄示例阈值。
- [引用复核](https://docs.typesafe.ai/cookbooks/citation_check)：代码先定位，再判断上下文支持关系；本项目不将自动判断当最终根因确认。
- [Confidence](https://docs.typesafe.ai/confidence)：分布统计量，阈值需按问题和风险验证。
- [Jev 已知局限](https://docs.typesafe.ai/model-jaggedness/jev-1.13)：数学、日期、间接判断、无关上下文、攻击与选项顺序等限制；相关计算留在代码中。
