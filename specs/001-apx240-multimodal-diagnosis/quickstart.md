# Quickstart and Acceptance Journey — Revision 2.2.0

2026-10-04. This is a future implementation validation guide, not a claim that the app or commands already run. Current workspace contains design artifacts only. Follow tasks.md to build, then record actual outputs.

## 1. Prerequisites and modes

Python3.11+, project-compatible pinned Node runtime, private PostgreSQL/pgvector and default MinIO. Compose may supply DB/MinIO; no-Docker mode uses an installed PostgreSQL plus filesystem media provider, never an in-memory graph DB. Local frontend/backend, database-backed in-process worker, no Redis requirement.

Keep supplied exam files private and imported locally by manifest; no public repository copy. Market models are fictional-equipment demonstration only, not real maintenance guidance. Configure local accounts/roles/event membership/qualifications via controlled management command; obtain sessions through login, never send self-assigned role JSON.

Modes:
- FIXTURE: deterministic state/contract/access testing; zero real-model quality claims.
- REAL_LOCAL: configured local market-model generation/embedding/OCR plus validated hardware; source processing remains private.
- REAL_APPROVED_EXTERNAL: explicitly permitted inputs and providers, actual model IDs/usage shown; source and incident permissions both required.
- Jev may be real on permitted simulation sources while original exam-source assessment is SKIPPED_POLICY. This is an honest mixed-mode demo, not full original-source external processing.

Future commands documented in README: start DB/storage, migrations, create demo accounts/qualifications, import local source release, start backend/worker/frontend, print health + browser URL, run fixture suite and real-provider suite separately. Scripts must check prerequisite services and print actionable failure. Actual invocation names are chosen in tasks; this guide deliberately does not imply nonexistent scripts succeeded.
